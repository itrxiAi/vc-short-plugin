# 拆活动为事件

把 `chapters/<章节号>/script.md` 的每个场景拆成活动清单，再把活动合并为事件，输出 `chapters/<章节号>/shot-split.md`。
本步只做结构化拆分，**不设计镜头、不写字段、不调用 CLI、不修改 script.md**。

## 范围边界

- 做：读 script.md → 合并事件 → 写 shot-split.md
- 不做：镜头职责、景别机位、首帧提示词、估时、编号、CLI 编译——这些归下游 skill

## Quick Start

无需 CLI。本 skill 纯文本处理，只用 read/write/edit。

## 入口

- 已执行 gen-script：读取 `chapters/<章节号>/script.md`，按场景拆分。
- 开始前读 `script.md` 的当前内容。用户说「剧本已确认」指的是那个文件，不是对话里更早的草稿；两者不一致时以文件为准，并把差异说出来。

## 核心定义

### 活动（activity）

- script.md 里**一行为一个活动**，可以是说话、动作、表情变化、`[画面文字]`
- 一个活动只做一件事：一句台词、一个动作、一个表情变化、一条画面文字
- 括号里的舞台指示（`（董问君老脸一红，目光躲闪）`）是独立活动，不算台词的一部分
- `[画面文字]` 标记行算一个活动

### 事件（event）

- **一组有因果关系或同时发生的活动**，合并为一个事件
- 合并依据：
  - **因果**：A 发生导致 B 发生（质疑 → 反击；揭短 → 反应）
  - **同时**：A 和 B 在同一时刻发生
- **一个事件的活动不超过 3 个**；超过 3 个说明该事件该拆成两个事件
- 单个活动也可独立成事件（如反应、环境动作），但优先找配对

## 工作流

1. **准备**：读 `chapters/<章节号>/script.md`。列出场景清单（SC 编号、地点），不展开。
2. **逐场景合并事件**：对每个场景，把 script.md 的行按因果/同时依据合并为事件，编号 E1、E2、E3……每个事件的活动按发生顺序连成一段写下来，标题用 `### E<编号>`。
3. **落盘**：每拆完一个场景，立即把该场景的事件段落追加写入 `shot-split.md`，再拆下一场景。**禁止把整章攒到最后一次性写入**——逐场景落盘后中断只丢正在写的那个场景。
4. **自查**：script.md 每行都归入某个事件（不能漏）；决定不拍的场次在 `shot-split.md` 开头写 `- 未拍场次：<场景 ID>（理由：……）`——漏拍和有意省略在成稿里长得一样，区别只在理由写没写；事件编号在场景内从 E1 起重新计数，连续无跳号；每个事件的活动不超过 3 个。
5. **完成**：列出全章事件总数请用户确认。

## 输出格式

`chapters/<章节号>/shot-split.md`，格式与 script.md 风格一致——每个事件一段，上面有个 `### E<编号>` 标题：

```markdown
# 事件拆分 — ch<章节号>

## SC001 <场景描述>

### E1
活动1
活动2

### E2
活动1
活动2


...

## SC002 <场景描述>

### E1
...
```

说明：活动 = script.md 中的一行（台词行、括号舞台指示行、标记行）。合并为一个事件的行连成一段写下来，保留 script.md 原文，不做改写。

## 修订

只改用户点名的场景；未点名场景的活动和事件保留不动。改完重写该场景块即可。

## 完成

每个活动都归入事件、事件编号连续无跳号，即完成。下游镜头设计 skill 从 shot-split.md 起步，不再回读 script.md 原文。
