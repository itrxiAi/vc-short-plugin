# 拆分分镜

把剧本和视觉事实转成有镜头职责、空间连续性和可生成首帧的 `chapters/<章节号>/shots.md`。
每镜使用二级标题 `## SHOT-场序-镜序`，同镜下用 `### 声音` 写对白正文、`### 首帧提示词` 写起始帧正文。

## Quick Start

`vcshort` CLI 固定安装在 `~/.vc-short/`（Windows 为 `%USERPROFILE%\.vc-short`），自带 Python 运行时：
- bash / Git Bash / macOS / Linux：`~/.vc-short/bin/vcshort <command> ...`
- Windows cmd / PowerShell：`%USERPROFILE%\.vc-short\bin\vcshort.bat <command> ...`

下文 `vcshort <command>` 均指上述完整路径。若该路径不存在：代用户安装运行时——下载 `https://github.com/itrxiAi/vc-short-plugin/releases/latest/download/vcshort-macos.zip`（Windows 用 `vcshort-windows.zip`），解压并把其中的 `vc-short-plugin` 文件夹移动为 `~/.vc-short`，装好后重试。

## 入口

- 已执行 gen-script：读取 `chapters/<章节号>/` 下的 `script.md`、`character_map.yaml`、`scene_map.yaml` 和项目 `config.yaml`，直接拆。映射文件不存在则 CLI 自动生成模板。
- 已有分镜：CLI 追加 `--force` 覆盖；只改部分镜头时保留未受影响的镜头 ID（见修订）。
- 开始拆分前读 `script.md` 的当前内容。用户说「剧本已确认」指的是那个文件，不是对话里更早的草稿；两者不一致时以文件为准，并把差异说出来。

## 工作流

1. **准备**：读取 `script.md`、`character_map.yaml`、`scene_map.yaml`、`config.yaml` 和 constraints.md。列出场景清单（SC 编号、地点、角色组），不展开设计。
2. **确认每个场景的动作、对白、声音、画面文字和转折由哪些镜头承载**。剧本每段制作相关内容都必须：被镜头落实、有理由地省略（在 shots.md 开头写 `- 未拍场次：<场景 ID>（理由：……）`）、或有新体验的重复。
3. **逐场景落盘**，按场景顺序拆分并写进 `shots.md`：每拆完一个场景，立即把该场景的镜头追加写入 shots.md（落盘），再拆下一场景。**禁止把整章内容攒在最后一次性写入**——单次输出过长会中途截断，攒着写中断即全部丢失；逐场景落盘后中断只丢正在写的那个场景。
   - **镜头职责**：本镜结束时观众或人物发生了什么变化——建立空间、展示证据、转移权力、表现反应、让后果无法回避。「中景展示人物说话」不是职责。
   - **状态链**：`起点 → 唯一动作 → 终点`。写清人物、双手、持物怎样从起点变到终点，不能靠镜外瞬移衔接；终点必须能成为下一镜的可信起点。
   - **对白估时**：先排完整声音事件，再定镜长。对白按约 4.5 字/秒估区间，加句间停顿和说完后的反应；边说边做的动作与对白并行计，必须等话说完的动作另占时间。动作按类型估时：打斗类约 5 秒；移动和肢体动作（移动物品、起身、走近）约 1-2 秒。取容得下的**最小合法档**（5/10/15 秒）；超过 15 秒按可见状态闭合点拆镜。不要先选短档再让人物加快语速。把估时依据简写在本镜「声音」字段里。
   - **景别机位最后选**：只在注意、压力、观众立场、揭示或节奏变化时改变。竖屏以中景/近景/特写为主，空间靠纵深分层交代。
4. **切镜与合并**：切镜必须带来信息、权力、情绪、空间或节奏变化；相邻两镜同景别、同角度、同人物关系 = 并回一镜。同一动作不跨镜重复发生。
5. **动作唯一落实**：转手、开门、受伤、亮出证物、揭面等动作，全章只有一个主要落实镜；其他镜只承担反应、细节或新信息。
6. **承受者反应**：打击、翻盘需要观众理解后果时，必须有可读的反应承载；现有画面已清楚就不补镜。
7. **首帧投影**：`### 首帧提示词` 只投影本镜起点——删掉终点才出现的动作完成态、过程中才露出的文字、转手后才易主的持物。写构图、站位、光线、持物，人物长相交给参考图。生成视频时 CLI 自动判断首帧来源：**同主号连续镜头直接用上一镜尾图**（last_frame.png）作起始画面，**新主号第一镜（地点或角色组变化）才按首帧提示词新建首帧图**；因此首帧提示词必须与上一镜终点一致，保证两条来源都能得到正确起点。
8. **自查**：对照 constraints.md 静默过一遍——每段剧本都有镜头承载或已记理由、字段完整、动作唯一落实、首帧投影、边界连续、估时容得下；发现问题直接修正 shots.md。
9. **编译**：跑 CLI 把 shots.md 编译成 shot YAML（见写入），列出所有分镜请用户确认。CLI 编译时做**场景覆盖核对**：script.md 每个 `SCxxx` 要么被某镜「来源」承载，要么已记入「未拍场次」并带理由，缺失则编译失败并点名缺失场景。**恢复规则**：核对报缺失时，只补写缺失场景的镜头（追加到 shots.md），不重写已有镜头——已有部分是上次输出的成果；补齐后重新编译。

## 镜头要求

- 每镜有唯一职责、明确来源（`来源` 字段写场景 ID + 短引文）、可见起止状态和合理时长
- `首帧提示词`、`终点` 写绝对事实，不用「同上」「保持不变」代替
- 相邻镜头的站位、朝向、视线、持物、伤势连续；同主号 position 连贯
- `角色` 的 position 参考同场景上一分镜推导：上一镜 `终点` 里某角色站在哪、朝向哪、持什么，本镜 position 就从那里接续，不得凭空重写；新主号（场景或角色组变化）才按剧本重新设定
- `角色` 列出本镜实际出场角色（含 position），不超过 4 人，超出用群体称呼替代
- 纯动作镜无需对白预算；内容不足选短档，不为凑满时长注水
- 动作写常见动作的组合与时机；精细编排（运动中截物、三步以上双手动作）图生视频不可用

## 编号规则

分镜号 = `场序-镜序`（如 `1-1`、`2-3`），对应剧本场景编号。CLI 编译后 YAML 存放在 `chapters/<章节号>/shots/shot_XXX_YY/shot.yaml`：
- `shot_001_01`、`shot_001_02` — **同一地点且角色组一致**的连续分镜（主号 001 相同，子号递增）
- `shot_002_01` — 地点或角色组发生变化后的第一个分镜
- **同主号必须顺序生成**（后一镜需要前一镜的 last_frame 保持连贯），**不同主号可并行**

## 分镜 Markdown 格式

```markdown
# 分镜 — ch01

- 未拍场次：SC003（理由：纯过场，无戏剧工作）

## SHOT-1-1

- 来源：SC001（陈青源被质疑夺舍）
- 职责：展示陈青源被质疑夺舍，让观众站到他这边
- 时长：10
- 景别：中景
- 机位：平视·固定
- 角色：陈青源@大殿中央, 姚素素@左侧首位
- 道具：玉镯@陈青源怀中
- 场景：玄青宗大殿
- 唯一动作：陈青源拱手回应质疑，姚素素冷笑发难
- 终点：陈青源站定，姚素素神色戒备

### 声音
陈青源（拱手）：各位师姐，我确实是陈青源。
姚素素（冷笑）：夺舍之身，也敢冒充？

### 首帧提示词
淡白长袍青年陈青源站在大殿中央，四周身着道袍的师姐围立，神色戒备，午后侧光
```

字段说明：
- `来源`：场景 ID + 短引文，追溯用，不进视频提示词
- `职责`：本镜结束时观众/人物发生了什么变化
- `时长`：5/10/15 三选一，按对白估时选取
- `景别`：中景/近景/特写/全景
- `机位`：`角度·运镜`（如 `平视·固定`、`俯视·缓慢平移`），单词默认运镜为固定
- `角色`：`角色名@位置, 角色名@位置`，position 写站位/持物/朝向
- `道具`：`道具名@本镜状态, 道具名@本镜状态`，state 写本镜开始时该道具的状态（如"在陈青源手中"、"未拆封"）；无状态变化可只写道具名
- `场景`：剧本场景描述，CLI 自动映射为 assets 目录名
- `唯一动作`：起点→终点的可见状态链，视频模型消费
- `终点`：下一镜起点须与此一致
- `### 声音`：对白/声音，`角色（动作）：台词` 格式，视频模型消费（解析说话人 + 构建叙述）
- `### 首帧提示词`：只写起点可见内容，删终点才有的东西

## 首帧来源

gen-video 按以下优先级取本镜起始画面：

1. 分镜目录已有 `keyframe.png`（用户手动生成过）→ 直接用
2. **同主号**上一镜已生成视频 → 提取其尾图 `last_frame.png` 作起始画面（天然连贯，不新建）
3. 都没有且加 `--with-keyframe` → 按 `首帧提示词` 新建首帧图

因此：**同主号子号递增的镜头，起点由上一镜尾图保证**；首帧提示词的价值在于文本约束（拼进视频提示词）和尾图缺失时兜底新建。新主号第一镜没有可借的尾图，首帧提示词是唯一起点来源，必须写全构图、站位、光线、持物。

## 写入

分镜文档写完后调用 CLI 编译为 shot YAML：

```bash
vcshort gen-shots <项目路径> --chapter <章节号> [--force]
```

脚本解析 `chapters/<章节号>/shots.md` 的 `## SHOT-XXX-XX` 块，生成 `chapters/<章节号>/shots/shot_XXX_YY/shot.yaml`。`角色` 用剧本角色名，`场景` 用剧本场景描述，脚本自动通过映射文件转为 assets 目录名；映射不到时保留原名称，可后续修改映射文件重新生成。`shots.md` 保留作为人可读的创作产物，不删除。

## 修订

保留未受影响的镜头 ID。拆镜、并镜或改变镜头职责时，说明哪些下游（首帧图、已生成视频）需要刷新，但不自动重写用户没点名的文件。

## 完成

点名范围的剧本段都有镜头落实或已记入未拍理由，每镜职责不重复、边界连续、首帧可生成，即完成。视频生成只有用户点名时开始（`/vc-short:gen-video`）。
