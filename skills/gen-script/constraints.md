# 剧本约束规则

本文件是剧本生成和审查的单一数据源。主 agent 生成时遵守，script-reviewer subagent 审查时对照。

发现矛盾一律对照 `novel.md` 原文核实，以原文为准。

## 0. 规则分级

| 级别 | 执行方式 |
|------|----------|
| **硬规则** | 违反必须修，审查可阻断：场景格式、禁止旁白、逻辑矛盾 |
| **戏剧规则** | 审查必须引用剧本证据指出，不能凭感觉扣分：场景戏剧性、对白行动、可表演载体 |
| **默认手艺** | 通常有帮助，创作者说明理由后可覆盖：晚进早出、巧合用法、收束方式 |
| **题材选择** | 类型套路不作为问题指出：打脸爽点、脸谱化反派、巧合制造麻烦 |

场景数量、对白比例、台词长度不属于质量证明，不作为审查项。

## 1. 场景格式（硬规则）

- 场景标题：`## SC001 内 · 地点 · 时间`，编号连续，内/外按现场，时间写大致时段
- 对白：`角色名（语气/表情）：台词`。括号里写语气、情绪或表情（「压低声音」「放缓」「冷笑」「皱眉」），不写策略、不写抽象内心状态
- 动作独立成行，用 `（）` 包裹，只写关键动作
- 生产标签按需使用：
  - `[画面文字]`：观众必须读清的文字（短信、纸条、屏幕）
  - `[VO]` / `[OS]`：当前管线不支持旁白，**禁用**


## 3. 逻辑矛盾（硬规则）

逐个场景与小说原文对比：

- 角色出场：剧本是否凭空增加了原文不在场的角色
- 事实设定：剧本中的关键设定是否与原文一致
- 角色称呼：同一场景中对同一角色的称呼是否统一，是否符合原文关系
- 人物位置：角色位置转换是否合理，原文是否有对应交代

## 4. 场景戏剧性（戏剧规则）

每个场景检查四问：

- **目标**：本场谁想让谁作出什么改变？目标要落成可执行动作（「在门关上前拿到钥匙」），不是「想获得尊重」
- **反对**：对方要什么，用什么筹码阻止？只会说「不」、只会挨打的对手要重写
- **转向**：哪项事实、筹码或决定使原计划失效？转向后人物不能照原样做——答案只是「更生气」不算转向
- **退出**：谁得到/失去什么，下一场为何现在必须发生？

场景必要性：删掉这场损失什么？答不上来 → 并进真正会转折的场景。

角色选择区分性格：本场谁做出了什么选择，这个选择只有这个角色会做吗？把两个角色的台词对调，如果分不出谁说的，说明人物没立住。性格不是标签（「洒脱」「阴险」），是在压力下的选择模式

重大信息后给有后果的反应：受影响者的下一步行为要改变，不是逐句配表情

失败征兆（命中即报）：

- 场景只传递信息，没有议程受阻或策略变化
- 角色轮流说出作者想让观众知道的内容
- 对手只会拒绝，主角只会重复要求
- 重大台词后人物行为完全不变
- 场景结尾恢复到进入状态
- 所有场景同一紧张度与句式

## 5. 对白行动（戏剧规则）

- 每句台词都在做事：逼问、试探、交换、威胁、划界、遮掩。标不出动作且不承担必要信息的句子，删掉或改成动作
- 说明性信息带立场或利益进入（争夺、交换、指控、回避），不由角色互述彼此都知道的背景
- 信息显式传递：AI 视频模型生成「两人对话」的画面是可靠的，信息可以靠对白传递，但每句交代信息的台词要带说话人的立场或利益，不是念说明书
- 说明性信息不要让一个人念长段背景，根据场景选择：
  1. **拆成交锋**：信息有争议或对方会反对时用。一方说诉求，另一方质疑/追问，信息在交锋中带出
  2. **只留诉求删背景**：背景前文已铺垫过时用。直接说现状+诉求，不重复已知信息
  3. **用反应带出**：信息需要体现对方态度时用。一方一句话带出信息，另一方用对白反应（不是微动作）接住，信息在反应中落地
- 对方反制后要换策略、付代价或退出，不重复原要求
- 台词「狠」或「金」但没让任何人改变行动 → 重写
- 一方持续发问、另一方持续完整回答 → 让回答方回避、反问或换条件

## 6. 可表演载体（戏剧规则）

- 内心状态（心虚、绝望、愤怒）必须有可见载体：行为选择、证据反应、空间动作、关系动作
- AI 视频模型能生成拍桌子、推搡、摔门而去、一群人围上来；看不懂手停住、眼神复杂、嘴角微动、手顿了一下。动作只写模型能生成的明显肢体动作，情感靠对白和大动作承载，不靠微动作
- **表情从固定词表选**：视频模型只能生成有限的大表情，写表情时从下表选一个，不要自造描述（「目光躲闪」「嘴角微翘」「眼神复杂」这类微表情模型生成不了，必须换成词表里的词）

  | 情绪 | 可见表达 |
  |------|----------|
  | 喜/乐 | 笑、咧嘴笑、大笑 |
  | 怒 | 皱眉、瞪眼、咬牙 |
  | 伤心 | 低头、垂眼、哭 |
  | 惊 | 瞪大眼、张嘴 |
  | 慌 | 四下张望、缩身、后退、流汗 |
  | 恐惧 | 后退、僵住、脸色发白 |
  | 思考 | 皱眉、低头、托腮 |

  微表情转译示例：「嘴角慢慢翘起」→「咧嘴笑」；「目光躲闪」→「慌」；「神色没起波澜」→ 删掉或转成对白。转译后删掉原微表情，只留词表里的表达
- 微表情（眉头微蹙、嘴角抽动、面色发白）、微动作（指尖轻颤、喉咙滚动、呼吸一滞）不能直接照搬——模型生成不了。情感信息要保留，载体换掉或删掉，**转译后删掉原微表情，只保留转译后的大动作/对白/道具**。根据上下文选择——
  1. **转成大动作**：微表情换成明显肢体动作。「眉头微蹙」→ 推开椅子站起身
  2. **转成对白**：微动作换成角色用对白接住信息。「指尖轻颤」→ 追问「你确定？」
  3. **转成道具/环境**：微表情换成道具动作或环境变化。「面色发白」→ 手里的杯子磕在桌沿，酒洒了出来
  4. **删掉**：情感信息不影响剧情理解时直接删掉，不强行转译
- 不写模型生成不了的：微动作、氛围描写（空气凝重、气氛尴尬）、心理活动（他心想、她感到）、精细编排（运动中截物、三步以上双手动作）——这些在真人剧里是高级技巧，在 AI 短剧里是废笔，模型要么忽略要么生成错，删掉或转成对白
- **生成模型约束**：动作写常见动作的组合与时机（压住、抽回、递出、锁上、挡住）；精细编排在生成管线里不可用，改用常见动作的组合承担同样的戏剧信息
- 动作简单流畅：只写关键动作，不照搬小说的详细叙述，让视频模型自行理解画面
- 冲突视觉化：冲突要落到可见的道具或显式的对白上（合同摔在桌上、钥匙被夺走），不靠气场、眼神、氛围这种模型生成不了的东西

## 7. 场景衔接（戏剧规则）

- 前场的退出状态就是后场的进入状态；对调两场而剧情无损，说明因果有问题
- 原文有时间/地点跨度的地方，剧本不能生硬跳过
- 角色去下一个场景的动机要有交代
- 背景叙述融入动作：小说里的环境描写、人物状态、时间跳跃不单独交代，融入动作和对白带出——
  1. **环境描写**（「酒馆里烟雾缭绕」）→ 融入动作里的细节（「他拨开缭绕的烟雾走进酒馆」），不单独描述
  2. **人物状态**（「他腿断了，走路要拄拐」）→ 通过动作展示（「他拄着拐杖一步步挪到桌边」），不用标签总结
  3. **时间跳跃**（「三天后」）→ 不写叙述，直接写下一个场景的第一个动作

## 8. 默认手艺（创作者可覆盖）

- 晚进早出：在压力已活跃处进入，在有意义的变化后离开，不写例行铺垫
- 巧合只制造麻烦，不解决麻烦；困境解除要靠人物策略
- 重要物件要进入行动链：谁持有、它证明或阻止什么、状态变化后谁做新决定
- 收束留残余：结尾不用口号总结意义，不硬加无关新事件；让行为和画面说话

## 9. 题材选择（不作为问题指出）

- 打脸、扮猪吃虎、脸谱化反派、为爽点服务的巧合制造麻烦——竖屏爽文的常规套路，照常使用
- 是否保留由创作者决定，审查不扣分
