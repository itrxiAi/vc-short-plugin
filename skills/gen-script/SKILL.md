# 改编剧本

## 前置条件

- 项目已初始化（有 `config.yaml` 和 `chapters/` 目录）

## 章节目录结构

```
chapters/ch01/
  novel.md      # 小说原文（用户输入或粘贴）
  script.md     # 改编剧本（本工作流生成）
```

## 输入参数

| 参数 | 说明 | 示例 |
|------|------|------|
| **项目路径** | 项目根目录的绝对路径 | `/Users/.../末日求生` |
| **章节号** | 章节编号 | `ch01` |

## 执行步骤

### 1. 收集参数

- 确认项目路径
- 确认章节号（如 `ch01`）

### 2. 检查小说原文

读取 `chapters/<章节号>/novel.md`：

- **有内容**：直接进入步骤 3
- **文件不存在或为空**：提示用户在对话框中直接粘贴小说原文，粘贴后将内容写入 `chapters/<章节号>/novel.md`

### 3. 抽卡式生成剧本（3 个 script-writer 并行）

先读取本 skill 目录下的 `constraints.md`，**严格遵守其中的约束规则**生成剧本。

并行启动 3 个 `script-writer` subagent，每个独立从小说原文改编一份剧本。3 个 subagent 互不知道彼此存在，各自独立生成，保证多样性。每个 script-writer 内部会自行完成"改编 + 启动 script-reviewer 审查 + 修订"闭环，返回最终剧本。

调用方式：

```
run_subagent(
  profile="script-writer",
  is_background=true,
  task="从小说原文改编为短视频剧本。\n\n约束规则：\n<粘贴 constraints.md 全文>\n\n小说原文：<项目路径>/chapters/<章节号>/novel.md"
)
```

改编原则和审查流程已内置在 `script-writer` profile 中，无需在 task 中重复传递。

3 个 subagent 全部使用 `is_background=true` 并行执行，等待全部完成后收集三份已审查修订的剧本。

**剧本格式：**

```
# 第X章 章节名 — 改编剧本

【场景1:地点】

角色名（动作/表情）：台词内容。

角色名：动作/表情

角色名：台词内容。

```

### 4. 主 agent 合并三份剧本

收集 3 份已审查通过的剧本后，主 agent 综合三者优点，生成最终剧本：

1. **逐场景对比**：按场景对齐三份剧本，对每个场景挑选最优版本（对白更自然、时长更合适、逻辑更通顺、更符合约束规则的那个）

2. **拼合成稿**：将各场景最优版本拼成完整剧本，确保场景间衔接顺畅
3. 写入 `chapters/<章节号>/script.md`

若某份剧本附有未解决问题清单（writer 第 4 轮仍未通过），在合并时一并记录，于步骤 5 展示给用户决定。

### 5. 确认结果

- 向用户展示合并后的剧本（附三份剧本的差异说明、综合理由、各份审查结果）
- 询问用户是否满意，不满意可修改后重新生成
- 确认后提示用户可以执行 `/vc-short:gen-shots` 拆分分镜

## 注意事项

- 剧本要适合短视频节奏，不要太长
- 每个场景要有明确的视觉描述，方便后续分镜
- 角色对白要自然，不要照搬小说原文
- 如果小说中有新角色或新场景，提示用户可能需要先执行 `/vc-short:extract` 提取资产
