# 改编剧本

## 前置条件

- 项目已初始化（有 `config.yaml` 和 `chapters/` 目录）

## 章节目录结构

```
chapters/ch01/
  novel.md      # 小说原文（用户输入或粘贴）
  script.md     # 改编剧本（本工作流生成）
```

## 输入参数

| 参数 | 说明 | 示例 |
|------|------|------|
| **项目路径** | 项目根目录的绝对路径 | `/Users/.../末日求生` |
| **章节号** | 章节编号 | `ch01` |

## 执行步骤

### 1. 收集参数

- 确认项目路径
- 确认章节号（如 `ch01`）

### 2. 检查小说原文

读取 `chapters/<章节号>/novel.md`：

- **有内容**：直接进入步骤 3
- **文件不存在或为空**：提示用户在对话框中直接粘贴小说原文，粘贴后将内容写入 `chapters/<章节号>/novel.md`

### 3. 改编剧本

先读取本 skill 目录下的 `constraints.md`，**严格遵守其中的约束规则**生成剧本。

LLM 将小说原文改编为短视频剧本，写入 `chapters/<章节号>/script.md`：

**剧本格式：**

```
# 第X章 章节名 — 改编剧本

【场景1:地点】

角色名（动作/表情）：台词内容。

角色名：动作/表情

角色名：台词内容。

```

**改编原则：**

- **角色自述**：小说原文交代一些背景信息，以及为了使场景间自然过渡，考虑通过角色自述来表现
- **保留对话**：相比于场景，动作，表情描写，应更注重对话
- **动作尽量简单流畅**：括号里的动作描写只写关键动作，不要照搬小说的详细叙述，让视频模型自行理解画面
- **场景化**：明确标注每个场景的切换，用 `【场景X:地点】` 分隔
- **角色名**：使用剧本中的角色名，后续分镜阶段再通过 character_map.yaml 映射到 assets 目录名
- **动作/表情**：（）表示可选输入，原文有说明动作表情时放入
- **剧本顺畅性处理**：小说原文中的场景/环境描写、时间/地点跨度、角色对话无法自然带出的背景信息，直接放入剧本会造成不顺畅。遇到这些情况时，在保证整体逻辑通顺的情况下让相关角色自述带出，让用户确认。
- **时长控制**：每个场景15s左右
- **场景拆分原则**：场景尽量少，需要填满 15 秒视频：
  - 对白字数判断（自然对白约 4 字/秒，15 秒约 40-60 字）
  - 2-3 句短对白 + 动作，或 1 段长对白，或一段复杂动作
  - 不要把一个完整动作或对白拆到两个场景
  - 内容不够撑起 15s 的场景应合并到相邻场景

### 4. 启动 script-reviewer subagent 全面审查

主 agent 不自行检查，将剧本交给 `script-reviewer` subagent 独立审查。subagent 有独立 context，不知道改编过程，从纯第三方视角逐项检查。

调用方式：

```
run_subagent(
  profile="script-reviewer",
  task="约束规则：\n<粘贴 constraints.md 全文>\n\n剧本内容：\n<粘贴 script.md 全文>"
)
```

将 **constraints.md 内容** 和 **剧本内容** 一起传给 subagent。subagent 有独立 context，看不到主 session 的对话历史和已读文件，必须显式传入约束规则，否则无法对照审查。subagent 会逐项检查场景时长、完整度、逻辑矛盾、场景切换，输出结构化审查结果。

**处理审查结果**：
- subagent 返回"全部通过" → 进入步骤 5
- subagent 返回问题清单 → 根据建议修改剧本，重新启动 subagent 审查，直至通过（最多 3 轮）
- 第 3 轮仍有问题 → 列出未解决问题，交给用户决定

每轮修改后更新 `script.md`，然后重新审查。

### 5. 确认结果

- 向用户展示检查通过的剧本（附检查报告）
- 询问用户是否满意，不满意可修改后重新生成
- 确认后提示用户可以执行 `/vc-short:gen-shots` 拆分分镜

## 注意事项

- 剧本要适合短视频节奏，不要太长
- 每个场景要有明确的视觉描述，方便后续分镜
- 角色对白要自然，不要照搬小说原文
- 如果小说中有新角色或新场景，提示用户可能需要先执行 `/vc-short:extract` 提取资产
