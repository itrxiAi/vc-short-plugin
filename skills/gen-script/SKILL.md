# 改编剧本

把一章小说原文改编成可拍摄的短剧剧本，写入 `chapters/<章节号>/script.md`。

剧本不是故事说明书，也不是镜头提示词。它要让分镜和视频生成从同一份文本中读出：谁想做什么，采取什么可见行动，局面在哪里改变。

## 前置条件

- 项目已初始化（有 `config.yaml` 和 `chapters/` 目录）

## 章节目录结构

```
chapters/ch01/
  novel.md      # 小说原文（用户输入或粘贴，或 crawl-novel 爬取）
  brief.md      # 本章简述（crawl-novel 生成，步骤 3 会读前后各 2 章）
  script.md     # 改编剧本（本工作流生成）
```

## 输入参数

| 参数 | 说明 | 示例 |
|------|------|------|
| **项目路径** | 项目根目录的绝对路径 | `/Users/.../末日求生` |
| **章节号** | 章节编号 | `ch01` |

## 执行步骤

### 1. 收集参数

- 确认项目路径
- 确认章节号（如 `ch01`）

### 2. 检查小说原文

读取 `chapters/<章节号>/novel.md`：

- **有内容**：直接进入步骤 3
- **文件不存在或为空**：提示用户在对话框中直接粘贴小说原文，粘贴后将内容写入 `chapters/<章节号>/novel.md`

### 3. 读相邻章节简述

读取本章**前 2 章**和**后 2 章**的 `chapters/<章节号>/brief.md`（存在才读，缺失跳过），用来把握本章在整体剧情中的位置：

- **前 2 章**：本章的进入状态从哪来——人物之前做了什么、带着什么压力
- **后 2 章**：本章的退出状态要往哪接——埋下的线在哪里被接住

相邻章简述只用于把握衔接，**不要写进本章剧本**，也不要因为后文而提前透露本章尚未发生的信息。

### 4. 改编剧本

先读取本 skill 目录下的 `constraints.md`，**严格遵守其中的约束规则**。改编按下面的流程走，中间产物（功能提取、场景规划）留在上下文里，不落盘。

#### 4.1 功能提取

通读 novel.md，把原文拆成情节点，每条一行四段：

```
P1 转折 | 林霸抢走小美的饼干，把她推倒在碎石地上 | 涉及：林霸、小美、饼干 | 功能：小美从忍让变成受害，给小帅入场制造理由
```

- **类型**：行动 / 对话 / 信息 / 转折 / 铺垫 / 兑现 / 状态
- **白描**只写原文写出来的可观察事实，不写心理断言——原文「她感到绝望」要落回「她做了什么」
- **功能**回答这一步改变了什么：信息、处境、关系、筹码、代价，至少一项。写不出功能的不是情节点
- 密度按原文调节，通常一个情节点覆盖 150-200 字；为同一个戏剧目的服务的连续微动作合并成一条

#### 4.2 锁定本章骨架

- **进入状态**：开场时人物知道什么、误信什么、带着什么压力
- **本章兑现**：观众看这一章要得到什么（爽点、悬念、关系变化）
- **退出状态**：章末谁在哪里、知道什么、哪项动作不可撤回——下一章从这里接

#### 4.3 场景规划

场景按戏剧工作切，**不按时长切**。一个场景值得存在，因为它完成了至少一项不可替代的工作：

- 目标遭遇有筹码的反对
- 证据被获取、争夺或毁坏
- 关系通过行动改变
- 人物作出带代价的选择
- 先前的后果抵达并封住旧路径

规划规则：

- **晚进早出**：在压力已活跃处进入，在有意义的变化后离开，不写例行铺垫
- **因果排序**：前场的退出状态就是后场的进入状态；对调两场而剧情无损，说明顺序有问题
- **合并**：只传递信息的段（纯铺垫、纯说明）并进真正会转折的场景。「删掉这一场损失什么」答不上来的场景不独立存在
- **纯文字快感**（内心独白、长篇心理描写、叙述性诡计）无法直接拍：转成对白、动作或删掉，背景信息用角色自述带出并让用户确认

#### 4.4 写正文

**逐场景落盘**：每写完一个场景，立即把该场景追加写入 `script.md`（落盘），再写下一场景。**禁止把整章内容攒在最后一次性写入**——单次输出过长会中途截断，攒着写中断即全部丢失；逐场景落盘后中断只丢正在写的那个场景，续写时先读 script.md 已有内容，从最后一个完整场景接着写。

**剧本格式：**

```md
# 第X章 章节名 — 改编剧本

## SC001 内 · 废弃学校操场 · 午后

（操场上搭满简陋帐篷，幸存者们缩在角落。林霸拎着搜刮来的物资走过。）

林霸（压低声音）：这些东西，以后归我管。有意见，现在提。

（人群沉默，无人敢应声。）

## SC002 外 · 操场角落 · 午后

（小美独自蹲在角落，怀里抱着一小袋饼干。）
```

**格式规则：**

- **场景标题**：`## SC001 内 · 地点 · 时间`，编号连续，内/外按现场，时间写大致时段
- **对白**：`角色名（表演提示）：台词`。表演提示写可执行策略（「把威胁说成通知」「改口前先确认对方不知道」），不堆情绪词；台词与动作已清楚时不写提示
- **动作**独立成行，用 `（）` 包裹，只写关键动作，不照搬小说叙述
- **生产标签**按需使用：`[画面文字]`（观众必须读清的字）。`[VO]`/`[OS]` 当前管线不支持旁白，禁用
- **角色名**用剧本中的名字，分镜阶段再通过 character_map.yaml 映射到 assets 目录名

**写作要求：遵守 constraints.md 的全部规则。**

#### 4.5 静默反查

交稿前只查一次，不落盘：

- 只看剧本，本章承诺的爽点/悬念能否被接收
- 人物行动是否有因果：每个主要动作因何发生、为何此刻、改变了什么、下一动作为何由此被迫发生
- 题材语气是否一致
- 只对本章实际启用的机关做专项检查（如写了艰难选择，两个方向在行动前是否都有价值）；没有的不查

若反查让剧本长出原文没有要求的机关（精确数字、记录链），撤掉机关而不是替它找理由。

### 5. 确认结果

- 向用户展示剧本
- 询问用户是否满意，不满意可修改后重新生成
- 确认后提示用户可以执行 `/vc-short:gen-shots` 拆分分镜

## 注意事项

- 场景数量和长度不是质量证明；场景由戏剧工作定义，删掉损失什么答不上来的场景不配独立存在
- 每个场景写清有用的空间事实：谁挡住出口、关键物件在谁手里、谁能看见什么——分镜和视频提示词靠这些生成画面
- 角色名用剧本中的名字，分镜阶段通过 character_map.yaml 映射到 assets 目录名
- 如果小说中有新角色或新场景，提示用户可能需要先执行 `/vc-short:extract` 提取资产
