# 改编剧本

把一章小说原文改编成可拍摄的短剧剧本，写入 `chapters/<章节号>/script.md`。

剧本不是故事说明书，也不是镜头提示词。它要让分镜和视频生成从同一份文本中读出：谁在争取什么，采取什么可见行动，局面在哪里改变。

## 前置条件

- 项目已初始化（有 `config.yaml` 和 `chapters/` 目录）

## 章节目录结构

```
chapters/ch01/
  novel.md      # 小说原文（用户输入或粘贴）
  script.md     # 改编剧本（本工作流生成）
```

## 输入参数

| 参数 | 说明 | 示例 |
|------|------|------|
| **项目路径** | 项目根目录的绝对路径 | `/Users/.../末日求生` |
| **章节号** | 章节编号 | `ch01` |

## 执行步骤

### 1. 收集参数

- 确认项目路径
- 确认章节号（如 `ch01`）

### 2. 检查小说原文

读取 `chapters/<章节号>/novel.md`：

- **有内容**：直接进入步骤 3
- **文件不存在或为空**：提示用户在对话框中直接粘贴小说原文，粘贴后将内容写入 `chapters/<章节号>/novel.md`

### 3. 改编剧本

先读取本 skill 目录下的 `constraints.md`，**严格遵守其中的约束规则**。改编按下面的流程走，中间产物（功能提取、场景规划）留在上下文里，不落盘。

#### 3.1 功能提取

通读 novel.md，把原文拆成情节点，每条一行四段：

```
P1 转折 | 林霸抢走小美的饼干，把她推倒在碎石地上 | 涉及：林霸、小美、饼干 | 功能：小美从忍让变成受害，给小帅入场制造理由
```

- **类型**：行动 / 对话 / 信息 / 转折 / 铺垫 / 兑现 / 状态
- **白描**只写原文写出来的可观察事实，不写心理断言——原文「她感到绝望」要落回「她做了什么」
- **功能**回答这一步改变了什么：信息、处境、关系、筹码、代价，至少一项。写不出功能的不是情节点
- 密度按原文调节，通常一个情节点覆盖 150-200 字；为同一个戏剧目的服务的连续微动作合并成一条

#### 3.2 锁定本章骨架

- **进入状态**：开场时人物知道什么、误信什么、带着什么压力
- **本章兑现**：观众看这一章要得到什么（爽点、悬念、关系变化）
- **退出状态**：章末谁在哪里、知道什么、哪项动作不可撤回——下一章从这里接

#### 3.3 场景规划

场景按戏剧工作切，**不按时长切**。一个场景值得存在，因为它完成了至少一项不可替代的工作：

- 目标遭遇有筹码的反对
- 证据被获取、争夺或毁坏
- 关系通过行动改变
- 人物作出带代价的选择
- 先前的后果抵达并封住旧路径

规划规则：

- **晚进早出**：在压力已活跃处进入，在有意义的变化后离开，不写例行铺垫
- **因果排序**：前场的退出状态就是后场的进入状态；对调两场而剧情无损，说明顺序有问题
- **合并**：只传递信息的段（纯铺垫、纯说明）并进真正会转折的场景。「删掉这一场损失什么」答不上来的场景不独立存在
- **纯文字快感**（内心独白、长篇心理描写、叙述性诡计）无法直接拍：转成对白、动作或删掉，背景信息用角色自述带出并让用户确认

#### 3.4 写正文

**逐场景落盘**：每写完一个场景，立即把该场景追加写入 `script.md`（落盘），再写下一场景。**禁止把整章内容攒在最后一次性写入**——单次输出过长会中途截断，攒着写中断即全部丢失；逐场景落盘后中断只丢正在写的那个场景，续写时先读 script.md 已有内容，从最后一个完整场景接着写。

**剧本格式：**

```md
# 第X章 章节名 — 改编剧本

## SC001 内 · 废弃学校操场 · 午后

（操场上搭满简陋帐篷，幸存者们缩在角落。林霸拎着搜刮来的物资走过。）

林霸（扫视人群，把威胁说成通知）：这些东西，以后归我管。有意见，现在提。

（人群沉默，无人敢应声。）

[连续性] 林霸右手始终拎着物资袋，直到 SC003 被小帅夺下。

## SC002 外 · 操场角落 · 午后

（小美独自蹲在角落，怀里抱着一小袋饼干。）
```

**格式规则：**

- **场景标题**：`## SC001 内 · 地点 · 时间`，编号连续，内/外按现场，时间写大致时段
- **对白**：`角色名（表演提示）：台词`。表演提示写可执行策略（「把威胁说成通知」「改口前先确认对方不知道」），不堆情绪词；台词与动作已清楚时不写提示
- **动作**独立成行，用 `（）` 包裹，只写关键动作，不照搬小说叙述
- **生产标签**按需使用：`[连续性]`（易丢失的状态变化）、`[画面文字]`（观众必须读清的字）、`[转场]`（有叙事意义的转场）。`[VO]`/`[OS]` 当前管线不支持旁白，禁用
- **角色名**用剧本中的名字，分镜阶段再通过 character_map.yaml 映射到 assets 目录名

**写作要求：**

- **场景发动机**：由冲突组织的场景，写前过四问——
  1. **目标**：本场谁想让谁作出什么改变？落成可执行动作（「在门关上前拿到钥匙」），不是「想获得尊重」
  2. **反对**：对方要什么，用什么筹码阻止？反对不是说「不」——换条件、质疑、拿走资源、让公开代价变高
  3. **转向**：哪项事实、筹码或决定使原计划失效？测试：转向前人物准备做什么，转向后为什么不能照做；答案只是「更生气」就不算转向
  4. **退出**：谁得到/失去什么，下一场为何现在必须发生
- **场景必要性**：删掉这场损失什么？答不上来就并进真正会转折的场景。铺垫场景也要完成变化（信息、压力、关系），纯氛围无变化的场删掉
- **对白是行动**：每句台词在做什么——逼问、试探、交换、威胁、划界。说明性信息带立场或利益进入（「你要真觉得这只是家店，就别拿母亲那把钥匙」优于「这家店是母亲开的」），不由角色互述彼此都知道的背景
- **可表演载体**：内心状态必须有可见载体——行为选择、证据反应、空间动作、关系动作。弱：「他很心虚，眼神复杂」；强：「他把盖章页翻过去，只递出没有签名的那一面」
- **生成模型约束**：分镜由图生视频生成，动作写**常见动作的组合与时机**（压住、抽回、递出、锁上、挡住）；精细编排（运动中截住某物、三步以上双手动作、厘米级位移）在生成管线里不可用，改用常见动作的组合承担同样的戏剧信息
- **动作简单流畅**：只写关键动作，不照搬小说的详细叙述，让视频模型自行理解画面
- **巧合方向性**：巧合只制造麻烦，不解决麻烦；困境解除要靠人物策略。误会产生后必须有人做出在真相下绝不会做的选择，解除时留残余
- **重大信息后给有后果的反应**：受影响者的下一步行为要改变，不是逐句配表情
- **收束留残余**：结尾不用口号总结已经演出来的意义（「物资是大家的」「眼里第一次有了光」这类删掉），不硬加无关新事件

#### 3.5 静默反查

交稿前只查一次，不落盘：

- 只看剧本，本章承诺的爽点/悬念能否被接收
- 人物行动是否有因果：每个主要动作因何发生、为何此刻、改变了什么、下一动作为何由此被迫发生
- 题材语气是否一致
- 只对本章实际启用的机关做专项检查（如写了艰难选择，两个方向在行动前是否都有价值）；没有的不查

若反查让剧本长出原文没有要求的机关（精确数字、记录链），撤掉机关而不是替它找理由。

### 4. 启动 script-reviewer 子代理全面审查

将剧本交给 `script-reviewer` 子代理（本插件 `agents/` 目录提供）独立审查，审查提示词见 `agents/script-reviewer.md`。

- 环境支持显式调用子代理时，传入 **constraints.md 全文**、**script.md 全文** 和 **novel.md 路径**（子代理有独立 context，看不到主 session 的对话历史和已读文件，必须显式传入约束规则，否则无法对照审查）
- 环境不支持子代理时：读取 `agents/script-reviewer.md`，主 agent 切换为纯第三方视角，严格按其审查流程逐项自查

子代理逐项检查格式与逻辑矛盾、场景戏剧性、对白行动、可表演载体、场景衔接，输出结构化审查结果。

**处理审查结果**：
- subagent 返回"全部通过" → 进入步骤 5
- subagent 返回问题清单 → 按问题分遍修改（一轮只解决该轮指出的一类问题，保留无关段落），更新 script.md 后重新审查，直至通过（最多 3 轮）
- 第 3 轮仍有问题 → 列出未解决问题，交给用户决定

### 5. 确认结果

- 向用户展示检查通过的剧本（附检查报告）
- 询问用户是否满意，不满意可修改后重新生成
- 确认后提示用户可以执行 `/vc-short:gen-shots` 拆分分镜

## 注意事项

- 场景数量和长度不是质量证明；场景由戏剧工作定义，删掉损失什么答不上来的场景不配独立存在
- 每个场景写清有用的空间事实：谁挡住出口、关键物件在谁手里、谁能看见什么——分镜和视频提示词靠这些生成画面
- 角色名用剧本中的名字，分镜阶段通过 character_map.yaml 映射到 assets 目录名
- 如果小说中有新角色或新场景，提示用户可能需要先执行 `/vc-short:extract` 提取资产
