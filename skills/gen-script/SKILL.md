# 改编剧本

## 前置条件

- 项目已初始化（有 `config.yaml` 和 `chapters/` 目录）

## 章节目录结构

```
chapters/ch01/
  novel.md      # 小说原文（用户输入或粘贴）
  script.md     # 改编剧本（本工作流生成）
```

## 输入参数

| 参数 | 说明 | 示例 |
|------|------|------|
| **项目路径** | 项目根目录的绝对路径 | `/Users/.../末日求生` |
| **章节号** | 章节编号 | `ch01` |

## 执行步骤

### 1. 收集参数

- 确认项目路径
- 确认章节号（如 `ch01`）

### 2. 检查小说原文

读取 `chapters/<章节号>/novel.md`：

- **有内容**：直接进入步骤 3
- **文件不存在或为空**：提示用户在对话框中直接粘贴小说原文，粘贴后将内容写入 `chapters/<章节号>/novel.md`

### 3. 改编剧本

LLM 将小说原文改编为短视频剧本，写入 `chapters/<章节号>/script.md`：

**剧本格式：**

```
# 第X章 章节名 — 改编剧本

【场景1：场景描述（含地点、环境、时间跨度等视觉信息，交给画面表现）】

角色名（动作/表情）：台词内容。

角色名：动作/表情

角色名：台词内容。

角色名：台词内容。
```

**改编原则：**

- **保留对话**：相比于场景，动作，表情描写，应更注重对话
- **动作尽量简单流畅**：括号里的动作描写只写关键动作，不要照搬小说的详细叙述，让视频模型自行理解画面
- **场景化**：明确标注每个场景的切换，用 `【场景X：描述】` 分隔
- **角色名**：使用剧本中的角色名，后续分镜阶段再通过 character_map.yaml 映射到 assets 目录名
- **动作/表情**：（）表示可选输入，需要强调动作表情时放入
- **剧本顺畅性处理**：小说原文中的场景/环境描写、时间/地点跨度、角色对话无法自然带出的背景信息，直接放入剧本会造成不顺畅。遇到这些情况时，给出使剧本顺畅的建议（如用场景镜头交代、让角色台词自然带出信息、或两者结合、或其他建议），让用户确认
- **时长控制**：每个场景15s左右
- **场景拆分原则**：场景尽量少，需要填满 15 秒视频：
  - 对白字数判断（自然对白约 4 字/秒，15 秒约 50-60 字）
  - 2-3 句短对白 + 动作，或 1 段长对白，或一段复杂动作
  - 不要把一个完整动作或对白拆到两个场景
  - 内容不够撑起 15s 的场景应合并到相邻场景

### 4. 自动检查与迭代

生成剧本后，不要直接交给用户。先执行以下 4 项检查，不通过就修改剧本，改完再查，循环直到全部通过（最多 3 轮）。

#### 检查 1：场景时长

逐个场景统计对白字数，按 4 字/秒估算时长（不含场景描写，只计角色台词）：

- **目标**：每个场景 15 秒（约 40-60 字）
- **太长**（>20s / >60字）：拆分为两个场景，或精简对白
- **太短**（<10s / <40字）：合并到相邻场景，或补充动作描写/对白

#### 检查 2：场景完整度

- **内容截断**：场景是否像被截断的片段（只有一两句对白 + 场景描写，没有完整情节）→ 合并到相邻场景或补充内容
- **动作拆分**：一个完整动作或对白是否被拆到两个场景 → 合并
- **空场景**：只有场景描写没有对白和动作的场景 → 合并或补充

#### 检查 4：逻辑矛盾（需对比 novel.md 原文）

逐个场景与小说原文对比，检查剧本是否与原文设定矛盾：
- **角色出场**：grep novel.md 中的角色名，确认该角色在原文对应段落中是否在场，剧本是否凭空增加了角色
- **事实设定**：剧本中的关键设定是否与原文一致
- **角色称呼**：同一场景中对同一角色的称呼是否统一，称呼是否符合原文关系
- **人物位置**：角色在 A 地，下一幕是否合理出现在 B 地，原文中是否有对应的位置转换

#### 检查 5：场景切换（需对比 novel.md 原文）

与原文的叙事节奏对比，检查场景过渡是否生硬：
- **遗漏转场**：原文中有时间/地点跨度的地方，剧本是否跳过了。grep novel.md 中的时间词（"次日""数日后""不久"），确认剧本是否保留了关键时间线索
- **情绪衔接**：原文中情绪转折的地方，剧本是否有对应过渡，还是直接从一种情绪跳到另一种
- **角色动机**：角色去下一个场景的原因，原文是否有交代，剧本是否保留

#### 迭代流程

```
第1轮：执行5项检查
  → 全部通过 → 进入步骤5
  → 有问题 → 修改剧本 → 第2轮
第2轮：执行5项检查
  → 全部通过 → 进入步骤5
  → 有问题 → 修改剧本 → 第3轮
第3轮：执行5项检查
  → 全部通过 → 进入步骤5
  → 仍有问题 → 列出未解决问题，交给用户决定
```

每轮修改后更新 `script.md`，然后重新检查。

### 5. 确认结果

- 向用户展示检查通过的剧本（附检查报告）
- 询问用户是否满意，不满意可修改后重新生成
- 确认后提示用户可以执行 `/vc-short:gen-shots` 拆分分镜

## 注意事项

- 剧本要适合短视频节奏，不要太长
- 每个场景要有明确的视觉描述，方便后续分镜
- 角色对白要自然，不要照搬小说原文
- 如果小说中有新角色或新场景，提示用户可能需要先执行 `/vc-short:extract` 提取资产
